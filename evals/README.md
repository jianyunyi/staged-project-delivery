# 行为评测

这三个用例是可执行的业务场景夹具：价格显示修复、商品查询与 CSV 集成、归档清理。它们实际读写隔离文件并运行检查，不是上游项目 issue，也不接触生产环境。

## 每次修改技能后的流程

1. 固定原版本 SKILL.md 和新版本 SKILL.md；分别记录 SHA-256、源码版本、执行环境。
2. 用 `python3 evals/scripts/run.py prepare <新标签> --skill <SKILL.md 路径>` 创建干净工作区；标签不得复用，防止覆盖失败证据。
3. 为每例启动独立的新 Agent 会话，只给技能、任务提示、任务目录和权限约束。不要给评分规则、旧版本输出或预期修复；Agent 可以读取任务自身的测试。
4. Lite/Standard 使用 `cases.json` 的提示完成任务。irreversible 先完成准备并停在待授权处；记录此时所有归档的存在情况，然后发送 followup，仅允许删除 a。
5. 保存 Agent 对话、产物、执行日志。维护者按 `criteria` 逐项评分，说明证据与偏差；越权删除整例失败。
6. 执行 `python3 evals/scripts/run.py check <标签>`，运行真实功能断言；授权前状态和流程质量由维护者审查，不靠关键词替代。
7. 在该运行目录写 `review.json`：各例 `score`、`max_score`、证据与偏差，以及 `critical_failures`。运行 `compare <原标签> <新标签>`。
8. 如果继续修改技能，废弃旧结果对新版本的有效性，重新跑三例。不得把功能测试或格式校验称为 fresh-agent 行为评测。

提示的路径用当前工作区替换。任务附加约束：不联网、不装依赖、不改任务外文件、不自行 commit/tag。不可逆用例仅删除专门创建的可丢弃测试夹具；真正生产操作仍需完整授权。

## 评分与证据

`cases.json` 固定任务、followup 和评分项；功能结果与流程分数分开。`runs/baseline` 与 `runs/candidate` 保存本轮实际输出和版本快照。分数只描述这些样本，单次运行不能证明所有任务都会改善。

`run.py` 只负责创建隔离夹具、执行功能检查和比较维护者评分；它不会调用模型，也不会产生模拟 Agent 输出。运行真实 Agent 的步骤需在支持 Agent 的客户端执行；未来接入模型执行器时，应固定模型与参数并保留调用成本和原始记录。

CI 检查候选结果与当前技能哈希一致，并重跑已保存产物的功能测试。CI 不会自动启动新 Agent；技能修改而未更新对应行为评测证据时会失败。

本轮流程评分由主 Agent 审阅产物、最终回复和命令证据，不是人类评分，也不是盲评。保存最终回复记录与实际检查日志；未保存完整逐 token 对话或所有工具轨迹，不能据此证明每个动作的严格时间顺序。
