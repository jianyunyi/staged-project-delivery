## 需求理解
我理解你的需求是：消费者或管理调用方需要按分类查阅商品，通过分页获取列表和匹配总数，并导出全部匹配商品。

范围：分类过滤、分页、CSV 集成与转义。不做：持久化、HTTP 服务、排序、新增 CSV 列、部署。
约束：只改当前目录，不联网、不安装依赖、不自行 commit/tag；设计与连续实施已授权。
假设：category 未提供时不过滤，提供时严格相等（空字符串也是分类）；缺省 page=1/pageSize=20；数字字符串不自动转换；保持输入顺序。CSV 保留 id,name,price 列，忽略分页选项，仅共享过滤。以上为实施选择而非额外用户要求。

## 方案
query.js 提供 filterItems(items,options) 与 query(items,options)。后者验证分页参数、过滤、计数后 slice，不修改输入。service.list 调用 query；service.exportCsv 调用共享 filterItems 后传给 csv，避免分页截断。
分页只接受 JavaScript 正安全整数；超大页返回空数组，避免偏移计算溢出。错误同步抛出，参数名明确。category 采用严格等值，undefined 表示无过滤。
csv.js 对每个单元格 String 转换；有逗号、引号、CR/LF 时加引号并将内部引号加倍。保留 LF 行分隔、原表头、无尾换行行为。空值序列化为空单元格。
关键选择：共享过滤而不复制逻辑；使用标准库、无新增依赖。替代：让导出使用 query 的分页覆盖值，容易耦合分页上限，故不采用。
失败路径：非法分页抛 RangeError；匹配为空返回空集合或仅表头。调用方搜索范围为当前目录所有 JS，入口仅 service.js。
