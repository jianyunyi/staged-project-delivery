# 项目文档模板

按模式精简章节：Lite 只用末尾的 `delivery-notes.md`；Standard/Full 用前三份。无论哪种模式，都保留需求映射、阶段退出标准、检查证据和沟通记录。尖括号为待填写内容，完成文档前替换，未知内容明确标注"待确认"。

每份文档顶部都有**状态块**。每次结束工作时更新它，续接时先读它。已关闭阶段的细节移到文档末尾的"历史"部分。

当前问题状态以总表为准；历史轮次记录保留原始状态，并标明历史。

问题级别（S0–S3）和类型（错误/告警/风险/限制）的定义见 SKILL.md 第 3 节。

## stage-report.md

追加每阶段记录和修复后补充记录，保留此前的失败证据。对话里只发短版（15 行以内），完整内容写在这里。

<!-- 状态块 -->

<通过/修复中/待沟通/阻塞，一句话理由>；独立复核：<已复核（谁/如何）/未独立复核/不适用>；检查点：<版本/哈希、证据、恢复步骤；提交授权来源（如适用）>

### 需要你决定的事

### 优化手段与效果

<内容、原因、影响、后续归属阶段>
