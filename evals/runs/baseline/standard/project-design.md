## 需求理解
我理解你的需求是：使用商品模块的调用方需要分类过滤、可靠分页和与列表条件一致的完整 CSV 导出。
范围：本目录 query.js、service.js、csv.js、真实自动化测试和三份阶段文档。
约束：不联网、不安装依赖、不修改其他目录、不 commit/tag；使用现有 CommonJS 和 Node 内置测试。
实施假设：分类按 category 严格相等，省略 category 为全部；分页默认 page=1、pageSize=10，接受 number 正安全整数及纯数字字符串（含前导零），不接受其他类型/格式。超过总页数返回空 items，total 仍为全部匹配数。CSV 空集保留表头和换行。导出忽略合法分页，但仍拒绝非法分页参数。

## 方案
共享 filterItems 处理分类和参数校验，query 使用过滤结果计算 total 后切片，service.list 返回结果对象。service.exportCsv 使用同一 filterItems 获取全量匹配项，再由 csv 编码三个字段。
关键选择：同步抛 TypeError/RangeError 表达错误，保持原模块调用方式；正安全整数避免 JS 精度丢失；页起点溢出时返回空页，避免舍入造成错误切片。
失败路径：非法分页在读取列表或导出时明确报错，无状态改变。输入数组只过滤/切片，不排序和修改。CSV 将字段转为字符串，对逗号、双引号、CR/LF 加双引号并将内部引号加倍。
风险：返回类型从数组改为对象是用户要求的接口变更，调用方需读取 items；采用内存过滤，与现有数据结构一致，不引入性能阈值。
